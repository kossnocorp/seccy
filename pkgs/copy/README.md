# Shared Fluent copy

`locales/en-US/seccy.ftl` owns the experimental native UI and notification copy.
The crate uses `fluent-bundle`, has no UI or key-store dependency, and can be called
by a future GTK frontend directly. Only English is shipped for now; there is no
language selector or runtime locale negotiation yet.

`Activity` contains semantic request information. `content(false)` renders a prompt;
`notification()` renders a completed action. The core crate maps observed process
and payload information into this type. Warning flags are separate from the text.
Inputs such as key names and usernames are literal values with control characters
escaped, never Markdown. Process chains and directory context must already be
sanitized by the caller (as `Caller::activity` does).

The legacy system prompt continues using the original description methods in
`core/src/prompt.rs` and `core/src/lib.rs`. Do not migrate or rewrite those messages
when editing Fluent copy. Regression tests pin their existing output.

## Swift and the gallery

Production passes the Fluent-formatted title, body, warning flag, and PID label in
its JSON request. Static UI labels (including authentication states), gallery
fixtures, and their notifications are generated by the same Rust formatter:

```sh
cargo run -p seccy_copy --example generate-swift
cargo run -p seccy_copy --example generate-swift -- --check
```

The checked-in `macos-ui/Sources/Copy.generated.swift` lets Swift Package tests and
Xcode previews run independently. Xcode builds regenerate it automatically; Cargo
builds generate their own copy in `OUT_DIR`. After editing Fluent, run the generator
before standalone `swift test`. Workspace tests reject a stale generated file.
Do not edit generated Swift or duplicate message text in the gallery.

Messages with arguments are resolved in Rust, not interpolated in Swift. New
runtime messages should be added to the presentation model. Static Swift labels
are exported from the `ui-`, `gallery-`, and `notification-error-` message groups.
The `ui-pid` message is resolved with the request's PID instead of exported as a
static label. When adding another language, both the runtime presenter and the
Swift projection need matching locale selection.
